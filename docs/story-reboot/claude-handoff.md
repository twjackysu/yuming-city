# Claude 接手：先重做前十分鐘，再決定是否展開

## 0. 狀態與優先順序

Jacky 在 2026-11-10 明確表示第一章就不知道在玩什麼，開場不吸引人；要求更接近轉生冒險漫畫，並使用現代好懂的詞語。本文件改寫任務與故事，不代表程式已實作，也不替實測下「一定好玩」結論。

基準 commit：ad8d5a8。現有引擎是 Godot，沿用。Codex 本次只交付敘事與任務設計，請不要把「劇情文件完成」當成「新版本已完成」。

先做下列 10 分鐘路線到第一次取得新能力並能試用為止。不要先做八章、技能樹、美術全面翻新、全新裝備庫或新增電影式過場。若基本揮擊、鏡頭或反饋不舒服，應先修這些；換故事無法替代操作品質。

## 1. 玩家每一刻都能回答的問題

1. 我現在要去哪裡或對付誰？
2. 我為什麼要做？
3. 剛剛我做了什麼有效的事？
4. 接下來有什麼想試的？

故事不要求新玩家先理解前世、階級、商會、職業和世界危機。開場只需「雇主丟下我，大怪追過來，我要帶這個人逃出去」。

## 2. 前十分鐘逐段腳本

時間為首次試玩設計預算，非強制倒數或已測結果。故事模式放寬攻擊窗口；看設定、看提示、暫停不計入體驗時間。

| 時間 | 玩家目標與行動 | 即時反饋 | 台詞／提示（草案） | 接下來的期待 |
|---|---|---|---|---|
| 0:00–0:15 | 已在北街，貨車、關閉的門、大怪都在視線內；很快取得控制 | 大怪砸下的第一擊打空，顯示危險方向，不強制扣血 | 諾恩：「工錢還沒拿，怎麼可以死！」目標「把貨車帶到街口」 | 我能否逃過追擊 |
| 0:15–1:00 | 移動、閃避；貨車採沿路推進與就近互動，不先實作完整載具駕駛 | 躲過一次清楚前兆；車上波克提醒車底發亮，敵胸同時亮 | 「車底有東西在發光。」只在需要時顯示閃避鍵 | 找到追我的原因 |
| 1:00–1:45 | 拆掉車底標記，丟到指定鐵桶 | 敵人轉頭砸桶，玩家立刻看到因果 | 「拆掉追蹤標記」→「把它丟進鐵桶」 | 能力真的能改變敵人 |
| 1:45–3:00 | 斷樑擋路；從報廢起重機拆固定器，接到預設鏈條兩端 | 接點亮起，不相容處不假裝能接；敵人被拖跪，斷樑裂開 | 「用固定器鎖住牠的鐵架。」簡短預覽連線，不開三頁教學 | 我能利用場景對付大怪 |
| 3:00–3:30 | 席菈加入；把貨車送進側門，護送暫告結束 | 受救者進屋；存檢查點；從逃生轉為主動戰鬥 | 席菈：「會打嗎？」諾恩：「剛學會一招。」目標「和席菈打倒守衛」 | 換我反擊 |
| 3:30–7:00 | 南街受損送葬者，單階段入門版；玩家打裂縫、失衡時叫席菈追擊 | 傷害、跪地、裝甲裂開與同伴追擊都能辨識；Boss 可被玩家實際擊敗 | 席菈：「先讓牠跪下！」成功後「就是現在！」 | 掌握一套有效合作 |
| 7:00–8:00 | 拆下反衝零件，自動裝到第一把可用武器；不要求懂背包管理 | 明確獲得永久可用的新工具，出示一句功能 | 「得到反衝零件：擋住撞擊，再打回去。」 | 立刻試新招 |
| 8:00–9:00 | 可重試的小測試；席菈慢速敲擊或用訓練裝置充能，打散木箱 | 正確時機亮起儲能；下一擊有清楚不同結果；失敗無永久成本 | 艾妲：「箱子七枚銅幣。妳提供的力，妳也付一半。」 | 新能力有用，角色也好玩 |
| 9:00–10:00 | 收回部分工錢，短對話後可直接前往地窖 | 有報酬、同伴加入；目標明確換成追討與追查 | 席菈：「證物歸我，其他對半。」諾恩：「不能整車都算證物。」 | 地下還有一車可拆的東西 |

### 不容改回去的底線

- 首次有意義的操作目標在 15 秒內出現；開場字幕可以跳過。
- 不先要求敲九次鐘、讀名單、搬三次瓦礫或吃兩頓飯。
- 受困者不作突然死亡的教學懲罰；失敗從近距離檢查點重試。
- 第一次勝利由玩家造成，不能最後全靠席菈的不可控大招。
- 不在得到裝備後立刻停 demo。給玩家測試空間，再讓他主動去下一個目標。
- 新故事沒有鐘導致災難、人生記憶扣除、替人燃燒肌腱或七年後預言。

## 3. 最小可行實作與新增成本

先在隔離的新流程中做，保留舊版可比對。新增起重機可用少量灰盒梁柱；用既有受損街道、車隊、鐵架、敵人、裂縫弱點、同伴和場景接點。不可宣稱只改 JSON 就能完成：

| 範圍 | 能重用的東西 | 必須真的修改／新增 |
|---|---|---|
| 追擊 | frostbridge 場景、Undertaker 移動與攻擊、車隊概念 | 目標切換、追蹤標記、路線觸發；先設計有限範圍，不能讓舊車隊成功旗標提前結束戰鬥 |
| 拆固定器 | 互動提示、物件狀態、九秒倒數呈現 | 新資源與接點狀態，取消 pay_memory；不可沿用舊刪記憶副作用 |
| 拖倒敵人 | 已有失衡、鐵架外觀、弱點 | 帶接點的鏈條灰盒、單次拖跪和開路回饋；不必先做自由繩索物理 |
| 正式協作戰 | 玩家近戰、閃避、鎖定、看穿、Q/E/R 指令 | 調入門招式、勝利條件與數值；角色自己造成的有效輸出需被看見 |
| 戰後反衝 | 打擊回饋與 UI 容器 | **目前未確認有格擋／儲能系統，須新增最小版本**；限定一個可防禦攻擊與一次釋放，不假設現有程式已有 |
| 探索與獎勵 | 任務、存檔、對話、日記 | 新旗標與零件資料、取得提示、試用場景；先固定裝備，不先建完整物品欄 |

若反衝實作尚未完成，測試版本可先讓固定器在第二場小遭遇重複使用並標明「第一項獎勵玩法未完成」。不能用一張獎勵卡或不可操作過場冒充驗收通過。

## 4. 對應現有檔案（均已確認存在）

### 第一優先：新開場

- `game/data/quests/slice_main.json`：目前為 explore_town → ring_bell → rescue → meet_sheila → escort_convoy → aftermath。新版需要獨立的新任務 ID 和階段，不能只換目標文字繼續跑敲鐘條件。
- `game/data/dialogue/slice_pear_seller.json`、`slice_sheila_meet.json`、`slice_ada_aftermath.json`、`slice_arch_memory.json`：新流程不再觸發父親記憶、死者責任、敲鐘審問。用 opening-v2 的人物動機改寫；完整小說文字不要全部塞入強制對話。
- `game/src/core/nine_breath.gd`：activate() 會直接 pay_memory(memory_id)，RESTORED 讀檔時視為 SPENT。這是舊單次犧牲設計，不能僅將提示改成「電量」。建議保留舊類給舊流程，另建具有供能、回收與重試語意的新能力狀態。
- `game/src/core/game_state.gd`、`save_codec.gd`、`story_logic.gd`：既有 memories_paid 與 memory_paid 條件留給舊檔讀取；新章節與零件需要獨立欄位／命名空間和版本。不要把讀過舊檔的記憶缺失帶進新故事。
- `game/scenes/world/nine_breath_site.gd`、`game/scenes/levels/story_level.gd`：提示與觸發可參考，場景邏輯必須讀新狀態，不再顯示永久代價。
- `game/i18n/slice.csv`、`strings.csv`：新增繁中與英文 key，維持重綁鍵及手把 glyph，文案寫操作效果。
- `game/tests/flow/test_frostbridge.gd`、`test_slice_playthrough.gd`、`test_gamepad_route.gd`：新流程單獨測；舊流程測試不能全改成永遠通過。

### 第二優先：先測開場，再換地下路線

- `game/data/quests/ch1_main.json`：舊版連續酒館、地圖、北街、油燈、樓梯、飯桌等，改為追查貨車 → 下城小戰 → 黑市驗貨 → 工坊試裝，生活對話放在玩家願意停留的據點。
- `game/data/quests/ch2_main.json`：isa_table、isa_volunteer、meet_leo、wall_carvings、curtain 舊流程不能支撐新故事。伊薩情報放到一次能行動的委託；主椅改成受困探路員留下的通訊／維修站，角色背管資產不必硬保。
- `game/data/quests/ch3_main.json`：沿用 canal、誘餌、煤車與同伴，煤車成功後仍進弱化 Boss 戰；失敗則多一項威脅，而非成功者沒戰鬥、失敗者才有戰鬥。
- `game/src/core/rhythm_trial.gd`、`heart_targets.gd`、`coal_drop.gd`、`hang_rope.gd`：評估重用機制，但語意改為機械追蹤與接點；觀察不強制七次試錯，倒吊不拉長成按住按鍵。
- `game/i18n/ch1.csv`、`ch2.csv`、`ch3.csv`：與新任務同步，不可新目標夾著舊失憶台詞。

## 5. 資產取捨

保留：霜橋鎮、雪景、木構房屋、梨攤、酒館、地窖階梯、白晝城、乾運河、煤車、主角與席菈模型、灰巡者與送葬者模型、既有 UI 和手把。

可改用途：鐘錘外觀先當工作短錘；大鐵架當守衛結構；鐘形機件可作背景機械；巨大眼睛作清理機伏筆；主角夾板只用作短期事故傷。

停止擴充：敲九下、壽命換水、主椅替死、記憶剪洞、法庭贖罪、世界回溯。既有檔案不用立刻刪，但新路線不要引用。

標題音樂與美術重製排在玩法驗證之後，避免又投入很多輪細節而開頭問題沒解。

## 6. 存檔、分支與上線

先用新故事專用入口／存檔槽，明示為「新版開場」。既有玩家舊檔保持可讀且不覆寫；不能把舊 stage ID 隨便映射到新任務，因為玩家已有的因果完全不同。

在新流程與讀檔測試通過前，不把現有 latest 開發版悄悄換成半套故事。使用者可測試新版 build；確認開場方向有效後，再更新主線文件、標題與發行說明。

## 7. 驗收：真的讓人玩，再問

工程驗收：
- 鍵鼠／手把能完成拆標記、接固定器、打 Boss、拿獎勵、試用及進地下入口。
- 每一檢查點重試與讀檔，不會重複扣資源、重複發獎、跳過戰鬥、卡在已消失的互動物。
- 新模式任何正常技能使用都不呼叫 pay_memory、不隱藏戀愛選項、不刪日記。
- 過場跳過後，玩家／車／敵人狀態一致；暫停與選單不偷跑倒數。

體驗驗收（設計目標，需實測）：
- 第 30 秒能說出「我在帶人逃過大怪」，不必知道全部背景。
- 第 3 分鐘能說出「我拆掉標記，讓牠改追；我能用破裝置的零件反擊」。
- 第 10 分鐘能說出新工具用途，並願意繼續試一次或去看地下那車零件。
- 觀察連續沒有決策、操作或新資訊的空檔；強制對話單段先以不超過 30 秒為目標，不靠機械加快字幕來達成。
- 問「哪個瞬間有趣、哪個瞬間不知道做什麼、想不想繼續」；不要只問「有沒有看懂世界觀」。

若玩家理解目標卻仍不想繼續，優先檢查攻擊手感、敵人反應、移動、鏡頭與獎勵試用。不要立即再加十頁背景或做第四章。
